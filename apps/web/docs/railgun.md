# RAILGUN case study

The [case study route](../app/[locale]/case-studies/railgun/page.tsx) renders the [page copy](../../../content/pages/en/case-studies-railgun.json) at `/case-studies/railgun`. The route is `ROUTES.railgun`, and the sitemap lists it. The Messaging page links to it from the RAILGUN card. The site-wide navigation overlays the cover and adjusts its text colour to the section beneath it.

The [1440px desktop frame](https://www.figma.com/design/MALNxrjLTCy0TA9vaWEwBs/Logos-Designs?node-id=3767-17031) and [393px mobile frame](https://www.figma.com/design/MALNxrjLTCy0TA9vaWEwBs/Logos-Designs?node-id=3777-17120) supply the layout and copy. The [code-layer prototype](https://www.figma.com/proto/MALNxrjLTCy0TA9vaWEwBs/Logos-Designs?node-id=3904-18706) supplies the timing and easing for the cover, section reveals, five-step transaction diagram, stack replay, and closing transition.

The cover aligns the visible heights of the Logos and RAILGUN marks. Dark backgrounds use `#132430`.

## Page structure

The page reads one `railgunCopy` section from the page copy and fails the build if it is missing. [`railgunCopySectionSchema`](../../../packages/content/src/schemas/pages/railgun.ts) validates it, with one object per chapter. The page renders the chapters in this order, each from its own file in `_sections/`: `hero`, `intro`, `basics`, `privacy`, `transaction`, `stack`, `production`, `prifi`, `build`, `closing` and `gateway`. Motion code lives in `_motion/`, and images live in `public/images/railgun/`.

Each chapter owns its copy. Where a chapter has a `lineBreaks` entry, update that entry alongside its corresponding text. Most text uses an entry only when it matches the copy once whitespace is removed, so a stale entry is ignored. The transaction diagram's first mobile caption is the exception: it shows `transaction.lineBreaks.mobile.caption0` as written, without that check. The authored desktop breaks apply from 1440px. Mobile breaks apply at the 393px reference width and its immediate neighbours. Other sizes wrap to available space. The transaction diagram pins only when its stage fits in the viewport. Its tabs work by click, tap and arrow keys. The hint beside the next-step button comes entirely from the `scrollClickAStep` copy ("Scroll, click a step or use ← →"), so both arrows are text and the page adds no icon after it.

The cover uses the prototype's three text-motion groups even when the approved mobile copy wraps onto four lines. On mobile, the title wraps within the cover's content width and scales down from the 56px reference size on narrower screens. The `intro` chapter shows four statistics, on desktop and mobile, in this order: 3+ yrs, $5.67B, ~1.6M messages a day published by broadcasters (`intro.label16m` and `intro.messagesADay`), and 0 ETH. The stack replay uses the prototype's packet travel distance across the shorter mobile card gaps. The `production` chapter shows the night mountain photo on its own, with no quote or attribution. The PriFi timeline contains seven transaction stages, with Ordering followed by a single Settlement, and the schema requires exactly seven entries in `prifi.stages`. On mobile, the vertical PriFi timeline is visible before the three cards reveal together. On desktop, the three timeline segments draw in sequence.

The `.cta` buttons use a 10px arrow (`.railgun-arrow`) centred on the label, the same size as the arrows on other pages. The `.arr` wrapper is a flex box and the svg is block-level, so the arrow stays level with the text when `:active` scales the button. On hover, the arrow slides 3px right using `--t-ui` with `--e-sweep` on both filled and outline buttons. The longer, eased slide keeps it visible on outline buttons, whose colours pass through low contrast as they swap.

The Gateway.fm card opens the prototype's preview panel. The page uses the shared site footer and newsletter form. `SiteFooterGate` wraps the footer in the `railgun-footer-theme` class and marks it as a dark header zone.
