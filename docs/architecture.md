# Architecture

How the logos-web workspaces fit together and how content flows from `content/**` through the build, the CMS and the funnel. Covers [`pnpm-workspace.yaml`](../pnpm-workspace.yaml), [`turbo.json`](../turbo.json), the six apps in [`apps/`](../apps) and the six packages in [`packages/`](../packages).

## Workspaces

Apps are entrypoints only. Shared logic lives in packages.

| Workspace                  | Package name              | Purpose                                                                              |
| -------------------------- | ------------------------- | ------------------------------------------------------------------------------------ |
| `apps/web`                 | `web`                     | Public Next.js 16 site, static export. Port 3000.                                    |
| `apps/cms`                 | `cms`                     | Payload CMS 3.x admin (Next.js 16 + Postgres). Port 3001.                            |
| `apps/api`                 | `api`                     | Public funnel intake endpoint (Next.js 16, no pages). Port 3003.                     |
| `apps/logos-crm`           | `logos-crm`               | Internal CRM (Next.js 16, Drizzle + Postgres). Port 3004.                            |
| `apps/logos-demos`         | `logos-demos`             | Logos stack demos (Next.js 16). Port 3005.                                           |
| `apps/past-present-future` | `past-present-future`     | SvelteKit app served at `/past-present-future`, fully prerendered. Port 3006.        |
| `packages/content`         | `@repo/content`           | Content schemas, loaders for `content/**`, GitHub mutation helpers, locale registry. |
| `packages/funnel`          | `@repo/funnel`            | Shared funnel form values (questions, option ids, required-field lists).             |
| `packages/ui`              | `@acid-info/logos-ui`     | React primitives and SVG icons, built to `dist/`.                                    |
| `packages/tokens`          | `@acid-info/logos-tokens` | Design tokens.                                                                       |
| `packages/types`           | `@repo/types`             | Payload-generated types (`src/payload.ts`), regenerated by `pnpm generate-types`.    |
| `packages/config`          | `@repo/config`            | Shared ESLint / TypeScript / Prettier config.                                        |

## Dependencies

Declared in each `package.json`; internal packages resolve via the `workspace:*` protocol.

- `apps/web` depends on `@acid-info/logos-ui`, `@acid-info/logos-tokens`, `@repo/content`, `@repo/funnel` and `past-present-future`.
- `apps/cms` depends on `@repo/content`.
- `apps/api` depends on `@repo/funnel`.
- `apps/logos-crm` depends on `@acid-info/logos-ui` and `@acid-info/logos-tokens`.
- `apps/logos-demos` depends on `@acid-info/logos-ui` and `@acid-info/logos-tokens`.
- `packages/ui` depends on `@acid-info/logos-tokens`.

`packages/ui` builds to `dist/` (via `tsup`); apps consume its compiled output through the package `exports` map. Turborepo's `dev` and `build` tasks declare `dependsOn: ["^build"]`, so upstream packages build before apps start.

## Content flow

- `content/**` is the production source of truth for page copy and structured data (pages, press, circles, builders-hub, site).
- `apps/web` reads `content/**` at build time through `@repo/content` loaders. It never calls the GitHub API at request time.
- The CMS does not write published content to its database. Payload's Postgres stores only users, sessions, drafts and PR cache. CMS edits become GitHub PRs to `develop` (see [`apps/cms/src/services/content-workflow/`](../apps/cms/src/services/content-workflow)), then `apps/web` picks them up on its next build from `master`.
- Schema changes follow the checklist in [`packages/content/AGENTS.md`](../packages/content/AGENTS.md).

## past-present-future copy step

`apps/web` depends on `past-present-future`, so its build runs first and [`apps/web/scripts/copy-past-present-future.sh`](../apps/web/scripts/copy-past-present-future.sh) copies the SvelteKit `build/` output into `apps/web/out/past-present-future`. In dev, `apps/web` proxies `/past-present-future` to the Vite server on port 3006 (see [`apps/past-present-future/vite.config.js`](../apps/past-present-future/vite.config.js)).

## Funnel at a glance

Three public funnel forms on `apps/web` post to one endpoint on `apps/api`, which forwards to Notion (and an n8n/Baserow webhook for the steward form). Full request flow, Notion schema and option maps: [`docs/funnel/README.md`](funnel/README.md).
