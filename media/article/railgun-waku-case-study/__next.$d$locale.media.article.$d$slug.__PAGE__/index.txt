1b:T1fb9,<p>Learn more about how RAILGUN uses Waku to build a privacy layer on top of EVM based chains</p>
<p><img alt="Railgun Case Study" src="/media-images/waku_71ae12b4c699_railguncover_250f99dbb7-dc3fc093-750.webp" srcset="/media-images/waku_71ae12b4c699_railguncover_250f99dbb7-dc3fc093-750.webp 750w, /media-images/waku_71ae12b4c699_railguncover_250f99dbb7-dc3fc093-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="1456" height="816" loading="lazy" decoding="async" /></p>
<p>Does your Dapp need to offer private on-chain transactions? The following scenarios are examples of users that have such privacy requirements:</p>
<ul>
<li><strong>Donations made for humanitarian reasons</strong>: A humanitarian cross-border organisation like <a target="_blank" rel="noopener noreferrer" href="https://www.unicef.org/">UNICEF</a> might not want to disclose their donations to specific countries or communities under crisis to avoid unwanted political tensions.</li>
<li><strong>Private expenses:</strong> Some web3 users might not wish to keep their private expenses transparent (for example - costs related to medical treatments).</li>
<li><strong>Public goods funding:</strong> Donars may wish to donate anonymously towards a public goods project.</li>
</ul>
<p>All the above examples are not possible directly with Ethereum since the blockchain is, by design, a public ledger. Continue reading to understand how Waku can offer your users privacy.</p>
<h4 id="the-transparent-nature-of-ethereum"><strong>The transparent nature of Ethereum</strong></h4>
<p>Ethereum does not provide privacy by default; every transactional data in the Ethereum network is transparent. Similar to Bitcoin, <em>Ethereum-based technologies are designed for pseudonymity and not anonymity</em>. Lack of privacy is one of the many factors hindering DeFi use cases, as many financial applications require transactional data that is not publicly available. This creates the demand for privacy solutions like RAILGUN - a privacy-preserving project built using Waku.</p>
<p>With RAILGUN, users can leverage various DeFi functionalities like lending, borrowing, swapping and trading tokens privately.</p>
<h2 id="what-is-railgun">What is RAILGUN?</h2>
<br/> 
<p><a target="_blank" rel="noopener noreferrer" href="https://github.com/Railgun-Privacy">RAILGUN</a> is an on-chain privacy system built for EVM-based blockchains. The RAILGUN community claims the project to be the only uncompromising on-chain privacy solution with unparalleled encryption, security, and with DeFi functionality on par with other leading wallets.</p>
<p>The core features RAILGUN provides are:</p>
<h6 id="zk-powered-security-and-resilience"><strong>ZK Powered Security and Resilience</strong></h6>
<p>RAILGUN uses Zero-Knowledge (ZK) cryptography to enable the private use of smart contracts and DeFi without leaving the user’s preferred chain. This makes the solution self-custodial and bulletproof for private transactions without requiring a new L2 validator. There is no bridge risk, preserving security and decentralisation. In short, RAILGUN is as secure as the EVM chain on which it is deployed.</p>
<h6 id="bonded-well-with-the-evm-ecosystem"><strong>Bonded well with the EVM ecosystem</strong></h6>
<p>RAILGUN is not a separate blockchain that stands alone from the EVM ecosystem. The project seeks to enhance privacy utilities for the EVM ecosystem with the least dependencies. It solves many interoperability issues that exist with the other pro-privacy chains. RAILGUN is embedded into the Ethereum ecosystem; users can access transactional data and liquidity on Ethereum.</p>
<h6 id="no-breaking-changes-in-the-ux"><strong>No breaking changes in the UX</strong></h6>
<p>The user experience is similar to leading self-custodial wallets like MetaMask to interact with Ethereum/EVM chains regarding liquidity and DeFi.</p>
<h2 id="components-of-railgun">Components of RAILGUN</h2>
<br/>
<p>The RAILGUN system has three key attributes:</p>
<p><img alt="RAILGUN Workflow" src="/media-images/waku_83ba5623390b_railgun1_c212050b94-79520861-750.webp" srcset="/media-images/waku_83ba5623390b_railgun1_c212050b94-79520861-750.webp 750w, /media-images/waku_83ba5623390b_railgun1_c212050b94-79520861-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="2633" height="1519" loading="lazy" decoding="async" /></p>
<ol>
<li><strong>RAILGUN Smart contracts</strong></li>
</ol>
<p>RAILGUN smart contracts enable Zero-Knowledge privacy for any on-chain dApp. By integrating these smart contracts, developers can provide an incognito-like experience for their users without affecting the user experience.</p>
<ol start="2">
<li><strong>RAILGUN’s Relayer network</strong></li>
</ol>
<p>RAILGUN is supported by a decentralised relayer network that submits transactional data into the blockchain. The relayer network is also expected to preserve privacy to meet their ‘privacy-first’ approach and end-user anonymity requirements.</p>
<ol start="3">
<li><strong>RAILGUN Wallets</strong></li>
</ol>
<p>RAILGUN does not have a single in-house official wallet but already has an ecosystem of wallets that integrate the RAILGUN smart contracts and run independently. Check out more about the RAILGUN wallets <a target="_blank" rel="noopener noreferrer" href="https://www.railgun.org/wallets.html">on their community-curated website</a>.</p>
<br/>
<h2 id="how-does-railgun-use-waku">How does RAILGUN use Waku?</h2>
<br/>
<p>Most of RAILGUN’s core functionalities are executed as on-chain transactions. However, RAILGUN’s infrastructure demands a network of privacy-preserving and decentralised relayers. These relayers should be able to submit user-signed transactions to the blockchain.</p>
<p><img alt="RAILGUN&#x27;s Waku usage" src="/media-images/waku_e00a4d7134ef_railgun2_6d80196eb5-217afe8e-750.webp" srcset="/media-images/waku_e00a4d7134ef_railgun2_6d80196eb5-217afe8e-750.webp 750w, /media-images/waku_e00a4d7134ef_railgun2_6d80196eb5-217afe8e-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="2633" height="1519" loading="lazy" decoding="async" /></p>
<h4 id="waku-as-a-relayer-network"><strong>Waku as a relayer network</strong></h4>
<p>Much of RAILGUN’s user experience and privacy features are powered by a relayer network provided by Waku. RAILGUN runs a self-federated network of <a target="_blank" rel="noopener noreferrer" href="https://github.com/waku-org/nwaku">nwaku</a> nodes that relay the transactions from the signer into the blockchain. <a target="_blank" rel="noopener noreferrer" href="https://github.com/waku-org/nwaku">nwaku</a> is a full node implementation of Waku that usually runs resource-rich environments. The <a target="_blank" rel="noopener noreferrer" href="https://github.com/waku-org/nwaku">nwaku</a> relayers advertise their fees, and the signer selects the most appropriate relayer that leverages Waku to submit the transactional data.</p>
<h4 id="high-level-architecture"><strong>High-level architecture</strong></h4>
<p>The current Waku integration with RAILGUN uses nwaku via REST API, and the users leverage the wallet functionalities with <a target="_blank" rel="noopener noreferrer" href="https://github.com/waku-org/js-waku">js-waku</a> , a lightweight implementation of Waku that makes it adaptable in resource-restricted environments like browsers and desktop apps.</p>
