3f:T52a3,<p>If you've ever used Linux, you already understand Logos.</p><p>A Linux distribution isn't just a kernel—it's the kernel plus a networking stack, a carefully chosen set of system services, and the applications that together create a complete operating system. Ubuntu, Arch, Fedora—even Android—all share the same Linux kernel, but each assembles a radically different experience on top of it.</p><p>Logos works the same way. At its foundation sits the <strong>Logos Kernel</strong>—a microkernel that handles the essential primitives every decentralised application needs. Above that, a networking layer provides peer discovery, connection management, and privacy-preserving communication through a mixnet. And above that sit <strong>modules</strong>—pluggable components for storage, messaging, blockchain, and whatever else developers need.</p><p>Logos ships with an opinionated default configuration—the kernel runtime, plus storage, messaging, and blockchain modules—that functions as Ubuntu does for Linux: a ready-made distribution that works out of the box. The <strong>Logos App</strong> is the launcher that starts this experience, but it's module-agnostic: it loads whatever module profile is configured, much like a desktop environment can run on any Linux distribution. Users choose which modules to run; developers can go further and assemble entirely different distributions with their own selection of modules and configurations.</p><h2 id="the-layers">The Layers</h2><p>The Logos tech stack is organised into distinct layers, each with a clear responsibility. From the bottom up:</p><h3 id="logos-kernel-the-foundation">Logos Kernel: The Foundation</h3><p>Every operating system needs a kernel, and the Logos Kernel follows the <strong>microkernel</strong> philosophy—it does as little as possible while enabling everything else. Unlike a monolithic kernel like Linux, where the networking stack lives inside the kernel itself, a microkernel pushes networking and most other services out into separate processes. Logos follows this principle: the kernel provides only the minimal runtime primitives, and networking runs as a distinct layer above it.</p><p>In traditional operating systems, microkernels handle only the most fundamental operations: process management, memory allocation, and inter-process communication (IPC). Everything else—file systems, networking, device drivers—runs as a separate process in user space, communicating through the kernel's IPC mechanisms.</p><p>The Logos Kernel applies this same principle. Implemented through <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-liblogos">liblogos</a>, it provides module lifecycle management (loading, starting, stopping modules), IPC between modules via Qt Remote Objects, and a host process that orchestrates everything. It doesn't store files, relay messages, or validate transactions—those responsibilities belong to the modules above it.</p><p>This separation matters. A bug in the storage module can't crash the messaging layer. A blockchain upgrade doesn't require rebuilding the kernel. Each component can be developed, tested, and updated independently—just as system services on Linux can be restarted without rebooting the machine.</p><h3 id="discovery-peering-and-mixnet-the-networking-stack">Discovery, Peering, and Mixnet: The Networking Stack</h3><p>Above the kernel sits the networking layer—analogous to the TCP/IP stack in Linux. This layer handles how Logos nodes find each other, establish connections, and communicate.</p><p>But unlike TCP/IP, this layer has privacy built in from the ground up. The <strong>mixnet</strong> protects messages during their outbound phase, routing them through multiple relay nodes and mixing traffic patterns so that observers can't determine who is talking to whom. A <a target="_blank" rel="noopener noreferrer" href="https://lip.logos.co/ift-ts/raw/extended-kad-disco.html#api-specification"><strong>capability discovery protocol</strong></a> lets nodes advertise and find peers of interest for their applications without centralised registries, and the peering layer manages connections across the decentralised network.</p><p>Think of it this way: in Linux, the networking stack doesn't care whether you're running a web server or a database—it just moves packets. The Logos networking layer is designed with the same principle: today, it treats all traffic alike, whether modules above it are storing files, sending chat messages, or processing transactions. Future requirements may introduce protocol-level distinctions, but the goal is a shared, private communication foundation that remains agnostic to what runs above it.</p><p>This is the layer where the AnonComms team's work lives—building the <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/anoncomms-pm/milestone/2">libp2p mixnet</a>, implementing <a target="_blank" rel="noopener noreferrer" href="https://lip.logos.co/ift-ts/raw/mix-spam-protection-rln.html">RLN-based DoS protection</a> to prevent spam without sacrificing anonymity, and developing the capability discovery protocol that lets the whole network self-organise.</p><h3 id="modules-the-system-services">Modules: The System Services</h3><p>This is where things get interesting. Sitting atop the networking layer are <strong>modules</strong>—self-contained components that provide specific capabilities. Logos ships with three foundational modules, but the architecture is open for anyone to create their own.</p><p><strong>Storage</strong> provides decentralised file storage and retrieval using content-addressed (CID-based) data. Need to host a frontend? Serve assets? Store user data without relying on corporate cloud providers? The <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-storage/logos-storage-nim">storage module</a> handles it. Developers interact with it through a straightforward API: store a file, get back a CID; provide a CID, get back the file.</p><p><strong>Messaging</strong> handles coordination—private, censorship-resistant communication between parties. It consists of two layers <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/logos-delivery">Logos Delivery</a> provides the transport—publish-subscribe messaging for reliable delivery; <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/nim-chat-poc">Logos Chat</a> uses Delivery as transport, providing encrypted 1:1 conversations and evolving toward group conversations. Both are being packaged as separate Logos Core modules—a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-delivery-module">Delivery module</a> and a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-chatsdk-module">Chat module</a>. The Chat module currently embeds Delivery directly; future versions will use the standalone module through the kernel's IPC.</p><p><strong>Blockchain</strong> provides decentralised compute and consensus. This isn't just another L1—it's a purpose-built blockchain using <strong>Cryptarchia</strong>, a private proof-of-stake consensus mechanism where validator identities and stake amounts remain hidden. The <strong>Blend Network</strong> provides network-level anonymity for block propagation. And the <strong>Logos Execution Zone (LEZ)</strong> enables programmable state—both public and private—where developers can deploy programs, run AMMs, transfer tokens, and create financial primitives with built-in privacy. The team recently published a <a href="/media/article/why-proposer-anonymity">Proposer Privacy blog post</a> explaining why this matters.</p><p><strong>User Modules</strong> are the wild card. Because Logos follows the microkernel pattern, anyone can build modules that plug into the same IPC infrastructure. The Logos Kernel loads them, manages their lifecycle, and enables them to communicate with other modules—whether they're Logos defaults or third-party additions. The new <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-module">logos-module</a> library and CLI tool abstract this interaction, and a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-module-builder">logos-module-builder</a> simplifies the build process. SDKs exist for <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-cpp-sdk">C++</a>, with Rust and other languages in development.</p><p>The module architecture mirrors how Linux system services work. Just as systemd manages daemons—starting, stopping, and monitoring them—liblogos manages modules. And just as Linux services communicate through D-Bus, sockets, or shared memory, Logos modules communicate through the kernel's IPC layer.</p><p><img alt="Logos Tech Stack diagram.jpg" src="/media-images/Logos_Tech_Stack_diagram_b908621e8c-1328a272-750.webp" srcset="/media-images/Logos_Tech_Stack_diagram_b908621e8c-1328a272-750.webp 750w, /media-images/Logos_Tech_Stack_diagram_b908621e8c-1328a272-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="2441" height="1844" loading="lazy" decoding="async"></p><h3 id="dapps-the-applications">Dapps: The Applications</h3><p>At the top of the stack sit the decentralised applications that people actually use. These compose the modules below them—a chat app uses the messaging module and the storage module; a DeFi application uses the blockchain module and the LEZ; a filesharing app uses the storage module.</p><p>The <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-app-poc"><strong>Logos App</strong></a> is the default launcher for the Logos stack—a shell that starts the runtime, loads the configured module profile, and provides a unified interface. Out of the box, it hosts "Simple Apps" for each default module: a wallet for managing tokens, a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-chat-ui">chat interface</a> for encrypted messaging, a filesharing tool for storing and retrieving files, and an explorer for inspecting blockchain and LEZ activity. A new <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-design-system">design system repository</a> provides unified UI components and styling across the platform.</p><p>But the launcher is just one way to run Logos. The headless <strong>Logos Node</strong> starts the same runtime without a UI—ideal for validators, infrastructure operators, or backend services. And because the distribution is defined by which modules are selected—not by the launcher—developers can assemble entirely different Logos-based stacks for their own use cases.</p><h2 id="where-it-stands-testnet-v0-1">Where It Stands: Testnet v0.1</h2><p>This isn't theoretical architecture. The first testnet is coming together, and recent engineering reports give a concrete picture of what's being built.</p><p><strong>The kernel is operational.</strong> liblogos loads modules from GitHub, the Logos App hosts module UIs, and the Logos Node runs headless with blockchain, storage, and chat nodes. The new <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-module/pull/1">logos-module</a> library and CLI tool abstracts module interaction, and a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-package-manager">package manager</a> using the lgx format handles installation and dependency resolution. The package manager has been <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-package-manager-module/pull/21">extracted as a standalone library</a> to improve modularity and reusability.</p><p><strong>The networking layer is advancing.</strong> The AnonComms team closed their DoS/Sybil protection deliverable with the publication of an <a target="_blank" rel="noopener noreferrer" href="https://lip.logos.co/ift-ts/raw/mix-spam-protection-rln.html">RLN DoS Protection LIP</a> for libp2p mix. The <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/nim-libp2p/pull/2055">capability discovery protocol implementation</a> is in review. Mix message routing works in simulation, with optimisations including <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/nim-libp2p/pull/2069">concurrent proof generation and delay</a> underway. The demo chat app has been <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-chat-ui/pull/4">enhanced with stats</a> and mix improvements for <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/nim-libp2p/pull/2066">tag management</a> and <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/nim-libp2p/pull/2067">node pool handling</a>.</p><p><strong>Storage is transitioning.</strong> The codebase has been fully rebranded—<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-storage/logos-storage-nim/pull/1387">Docker images renamed</a>, <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-storage/logos-storage-nim/issues/1396">final Codex references removed</a>—and the v0.3.0 release suspended marketplace components to focus on filesharing. An <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/rfc-index/pull/281">improved Merkle tree spec</a> has been published and is under review. Provider anonymity research is progressing through study of the <a target="_blank" rel="noopener noreferrer" href="https://hackmd.io/@codex-storage/Hyy8v2nrZg">echomix pigeonhole storage protocol</a>. A <a target="_blank" rel="noopener noreferrer" href="https://github.com/gmega/easylibstorage">simple C wrapper over libstorage</a> with example <a target="_blank" rel="noopener noreferrer" href="https://github.com/gmega/easylibstorage/blob/main/examples/uploader.c">uploader</a>, <a target="_blank" rel="noopener noreferrer" href="https://github.com/gmega/easylibstorage/blob/main/examples/downloader.c">downloader</a>, and <a target="_blank" rel="noopener noreferrer" href="https://github.com/gmega/easylibstorage/blob/main/examples/storageconsole.c">console application</a> makes integration more accessible. The module integrates with Logos Core, with <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-storage-ui/pull/3">UI migrating from QWidgets to QML</a>.</p><p><strong>Messaging is taking shape.</strong> The Logos Delivery <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/logos-delivery/pull/3669">Send API</a> and <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/logos-delivery/issues/3646">Health API</a> are complete, with the Receive/Subscribe API in progress. The <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-delivery-module">Logos Delivery module</a> for Logos Core is ready alongside a <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-chatsdk-module">Logos Chat module</a> and demo <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-chatsdk-ui">Logos Chat UI module</a>. Logos Chat has working <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/libchat/pull/32">double-ratchet encryption</a> with <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/libchat/pull/25">FFI bindings</a>, <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/libchat/pull/24">conversation initialization</a>, and <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-messaging/libchat/pull/44">payload handling</a>.</p><p><strong>Blockchain is maturing fast.</strong> Leaders can now claim rewards anonymously through <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/2050">Proof of Claim</a>. The <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/2088">Zone-SDK v0</a> supports end-to-end inscription posting. A <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/lssa/pull/316">Sequencer-Indexer-Explorer integration</a> is underway for LEZ, backed by a <a target="_blank" rel="noopener noreferrer" href="https://www.notion.so/Sequencer-Indexer-architecture-2f68f96fb65c8047bb80e3bfd210be1e">Sequencer-Indexer architecture document</a>. Research into <a target="_blank" rel="noopener noreferrer" href="https://www.notion.so/Private-accounts-owned-by-multiple-users-2f78f96fb65c8030a814fadd3bab79d0">multi-owner private accounts</a> and <a target="_blank" rel="noopener noreferrer" href="https://www.notion.so/LSSA-2d78f96fb65c80329551fed21a8d8675?p=2f68f96fb65c80d996d2f5cfcdc62616&amp;pm=s">chain calls</a> is documented and being implemented. The <a href="/media/article/why-proposer-anonymity">Proposer Privacy blog post</a> and <a target="_blank" rel="noopener noreferrer" href="https://www.youtube.com/watch?v=RLiZLA0EdK8">Overwatch framework presentation</a> at Logos Dev Club mark growing public communication.</p><p><strong>RLN is a cross-cutting success story.</strong> The <a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/anoncomms-pm/milestone/4">RLN Prover milestone</a> for gasless L2 transactions is complete, including a <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/rfc-index/pull/286">whitepaper draft</a>. <a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/zerokit/pull/375">Multi-burn RLN proof support</a> is implemented. An <a target="_blank" rel="noopener noreferrer" href="https://github.com/status-im/status-network-monorepo/pull/139">RLN aggregator node</a> for authenticated slashing is launched. And RLN membership allocation through LEE programs with Merkle trees is progressing—connecting the blockchain and anonymous communications teams in a concrete, shared deliverable. The Storage team's <a target="_blank" rel="noopener noreferrer" href="https://forum.vac.dev/t/speeding-up-rln-proofs/663">blog post on speeding up RLN proofs</a> exemplifies the cross-team collaboration driving this forward.</p><h2 id="why-this-architecture-matters">Why This Architecture Matters</h2><p>Most blockchain projects build monoliths—single systems where consensus, execution, storage, and networking are tightly coupled. Upgrading one component means upgrading everything. Privacy is an afterthought bolted on at the application layer while metadata leaks freely at every layer below.</p><p>Logos takes a fundamentally different approach.</p><p><strong>Modularity means resilience.</strong> Each layer and module can be developed, audited, and upgraded independently. A storage bug can't take down messaging. A consensus upgrade doesn't require rebuilding the networking stack. This isn't just good engineering—in adversarial environments, it's a survival trait.</p><p><strong>Privacy is structural, not cosmetic.</strong> The mixnet obscures communication patterns at the networking layer. Cryptarchia hides validator identities and stakes at the consensus layer. The LEZ supports private state at the execution layer. Storage research is advancing <a target="_blank" rel="noopener noreferrer" href="https://hackmd.io/@codex-storage/Hyy8v2nrZg">provider and publisher anonymity</a>. Privacy isn't an application-layer feature but a property of the infrastructure itself.</p><p><strong>Composability enables sovereignty.</strong> When you run a Logos node, you're running infrastructure you control. Your messages don't route through company servers. Your files don't sit in corporate data centres. Your transactions don't require permission from intermediaries. And because the stack is modular, you choose exactly which capabilities you need.</p><h2 id="building-on-logos">Building on Logos</h2><p>If you understand how Linux works, you understand Logos.</p><p>The kernel handles the fundamentals. The networking layer connects nodes privately. Modules provide capabilities. Applications deliver value to users. Your choice of modules defines your distribution—and just like Linux, the whole stack is open for you to modify, extend, and make your own.</p><p>Testnet v0.1 is where this architecture becomes tangible—where you can run a node, store a file, send a message, transfer tokens, and push messages through a mixnet. Not on someone else's infrastructure. On yours.</p><p>&nbsp;</p><p><i>Logos is an open-source movement to revitalise civil society.
