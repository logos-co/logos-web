10:T1f5f,<p>Logos provides monthly updates on the state of the technology stack and the development of its various modules, giving developers a clear snapshot of development highlights from the past month.&nbsp;</p><p>August's work centred on the consensus layer of the Logos Blockchain, with uncle references and compressed block proposals both landing, alongside a finalised specification for the Logos Oracle Zone and a full redesign of the library delivering spam resistance across the stack. These updates further enhance the integrability and privacy-preserving capabilities of modules while hardening the overall stack.</p><p>The updates listed here are some of the most important highlights from the past month. Work progresses on many facets of the stack simultaneously, and a more complete, technical breakdown is available at&nbsp;<a target="_blank" rel="noopener noreferrer" href="http://roadmap.logos.co">roadmap.logos.co</a>.</p><p>For developer-focused highlights on X, please follow&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://x.com/Logos_devs">Logos Tech</a>. For broader updates on the Logos movement as a whole, stay tuned to the main&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://x.com/Logos_network">Logos</a> account.</p><h2 id="uncle-references-in-cryptarchia">Uncle references in Cryptarchia</h2><p>Cryptarchia is the privacy-preserving leadership lottery of the Logos Blockchain, where singular stakes are never revealed. The total therefore has to be inferred from block production.</p><p>Cryptarchia blocks now carry&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/3285">uncle references</a>, restoring discarded evidence and keeping Total Stake Inference accurate as delay rises.&nbsp;</p><p>The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/research/tree/master/reports/tsi">Total Stake Inference report</a> sets out the method in full..</p><h2 id="compressed-block-proposals">Compressed block proposals</h2><p><a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/3258">Compressed block proposals</a> are now working end to end, including support in Blend. Proposals reference their transactions by a short prefix rather than a full hash, with the serialisation aligned between the implementation and the specification.</p><p>Proposal size falls by roughly half as a result, and because every proposal travels over Blend, that reduction reduces the bandwidth Blend requires of the nodes running the protocol.</p><h2 id="channel-participation-in-proof-of-stake">Channel participation in Proof-of-Stake</h2><p>The Logos Blockchain token does two jobs. It secures the network through Proof-of-Stake, and it bridges into zones so applications can use it. Once bridged, funds were unable to participate in consensus and shrank the stake securing the network.</p><p>The Channel Participation in Proof-of-Stake&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-lips/pull/364">LIP</a> removes that trade-off, allowing bridged funds become on-ledger channel notes and allowing channels to redistribute the rewards earned on bridged funds to their users.</p><h2 id="the-logos-oracle-zone-specification">The Logos Oracle Zone specification</h2><p>The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://lip.logos.co/anoncomms/raw/logos-oracle-zone.html">Logos Oracle Zone specification</a> is now finalised. The design is optimistic and stays lightweight for the Logos Execution Zone by outsourcing signature verification to the Logos Blockchain, with the execution zone checking signatures only when a price is disputed.</p><p>Work on implementation continued alongside the specification, with the proposer selection mechanism merged, a first oracle register contract built, and the indexer now able to follow and compute an attested price per channel and feed.</p><h2 id="the-de-mls-boundary-contract">The de-MLS boundary contract</h2><p>A new research discussion was opened around the&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://forum.research.logos.co/t/de-mls-boundary-contract/727">de-MLS boundary contract</a>. De-MLS runs a decentralised MLS conversation driven purely by the application that calls it.</p><p>The central property is passivity. De-MLS performs no network operations, so it acts only when the application calls it, and every call hands back the time remaining until the next one is due. Storage, identity, and transport are operated by the application, while the group handle and every protocol decision belong to de-MLS.</p><h2 id="zerokit-v3-0-0-launched">Zerokit v3.0.0 launched</h2><p>Zerokit is the Rust implementation of Rate Limiting Nullifier, the anonymous rate-limiting primitive that underpins spam resistance in Logos. The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/zerokit/releases/tag/v3.0.0">latest version</a> is a full redesign of its internals, public API, and FFI and WASM boundaries.</p><p>The headline change moves mode selection from a compile-time feature to runtime and type-level configuration, so behaviour is chosen when the library is used rather than fixed when it is built. State is now a type-state on RLN, the tree backend is now a type parameter, and message-id mode is now a runtime enum.</p><h2 id="logos-delivery-module-update">Logos Delivery module update</h2><p>A&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-delivery-module/releases/tag/v0.2.1">new version of the Logos Delivery module</a> is live and fully backwards compatible, so existing integrations need no changes to integrate the latest version. It brings a newly bundled logos-delivery, tighter handling of calls, and Store and Postgres fixes addressing partition bloat and leaks.</p><p>The Messaging API itself is unchanged in this release.</p><h2 id="a-tutorial-for-the-storage-api">A tutorial for the Storage API</h2><p>A&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://docs.logos.co/storage/build-app/build-cli-app-that-uses-storage-api">new tutorial</a> was published in the Logos documentation. It covers building a Logos Core module that wraps the asynchronous Storage API in a synchronous command-line tool, then publishing a file and downloading it back by content identifier.</p><p>The tutorial joins the wider body of storage documentation recently migrated onto&nbsp;<a target="_blank" rel="noopener noreferrer" href="http://docs.logos.co">docs.logos.co</a>, and is accurate for Testnet v0.2.1.</p><h2 id="logos-broadcast-network-and-circles">Logos Broadcast Network and Circles</h2><p>Throughout August, Logos contributors continued to host online and IRL Circles around the world, creating digital and physical space to solve real-world problems with privacy-preserving technology.</p><p>The Logos Broadcast Network continued to deliver regular programming, from Dev Club sessions and weekly technical updates to office hours every Friday at 14:00 UTC. Join these office hours to learn more about building on the Logos stack or to get help with specific issues.</p><p>Full schedules and participation details are available at&nbsp;<a href="/logos-broadcast-network">press.logos.co/calendar</a> and&nbsp;<a target="_blank" rel="noopener noreferrer" href="http://logos.co/circles">logos.co/circles</a>. For a full list of upcoming Logos events, check out the event page on&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://luma.com/logosevents">Luma</a>.</p><p>To get the latest developer updates from the Logos stack, follow&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://x.com/Logos_devs">Logos Tech</a> on X.
