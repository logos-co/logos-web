The total therefore has to be inferred from block production.</p><p>Cryptarchia blocks now carry&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/3285">uncle references</a>, restoring discarded evidence and keeping Total Stake Inference accurate as delay rises.&nbsp;</p><p>The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/research/tree/master/reports/tsi">Total Stake Inference report</a> sets out the method in full..</p><h2 id="compressed-block-proposals">Compressed block proposals</h2><p><a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain/pull/3258">Compressed block proposals</a> are now working end to end, including support in Blend. Proposals reference their transactions by a short prefix rather than a full hash, with the serialisation aligned between the implementation and the specification.</p><p>Proposal size falls by roughly half as a result, and because every proposal travels over Blend, that reduction reduces the bandwidth Blend requires of the nodes running the protocol.</p><h2 id="channel-participation-in-proof-of-stake">Channel participation in Proof-of-Stake</h2><p>The Logos Blockchain token does two jobs. It secures the network through Proof-of-Stake, and it bridges into zones so applications can use it. Once bridged, funds were unable to participate in consensus and shrank the stake securing the network.</p><p>The Channel Participation in Proof-of-Stake&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-lips/pull/364">LIP</a> removes that trade-off, allowing bridged funds become on-ledger channel notes and allowing channels to redistribute the rewards earned on bridged funds to their users.</p><h2 id="the-logos-oracle-zone-specification">The Logos Oracle Zone specification</h2><p>The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://lip.logos.co/anoncomms/raw/logos-oracle-zone.html">Logos Oracle Zone specification</a> is now finalised. The design is optimistic and stays lightweight for the Logos Execution Zone by outsourcing signature verification to the Logos Blockchain, with the execution zone checking signatures only when a price is disputed.</p><p>Work on implementation continued alongside the specification, with the proposer selection mechanism merged, a first oracle register contract built, and the indexer now able to follow and compute an attested price per channel and feed.</p><h2 id="the-de-mls-boundary-contract">The de-MLS boundary contract</h2><p>A new research discussion was opened around the&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://forum.research.logos.co/t/de-mls-boundary-contract/727">de-MLS boundary contract</a>. De-MLS runs a decentralised MLS conversation driven purely by the application that calls it.</p><p>The central property is passivity. De-MLS performs no network operations, so it acts only when the application calls it, and every call hands back the time remaining until the next one is due. Storage, identity, and transport are operated by the application, while the group handle and every protocol decision belong to de-MLS.</p><h2 id="zerokit-v3-0-0-launched">Zerokit v3.0.0 launched</h2><p>Zerokit is the Rust implementation of Rate Limiting Nullifier, the anonymous rate-limiting primitive that underpins spam resistance in Logos. The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/vacp2p/zerokit/releases/tag/v3.0.0">latest version</a> is a full redesign of its internals, public API, and FFI and WASM boundaries.</p><p>The headline change moves mode selection from a compile-time feature to runtime and type-level configuration, so behaviour is chosen when the library is used rather than fixed when it is built. State is now a type-state on RLN, the tree backend is now a type parameter, and message-id mode is now a runtime enum.</p><h2 id="logos-delivery-module-update">Logos Delivery module update</h2><p>A&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-delivery-module/releases/tag/v0.2.1">new version of the Logos Delivery module</a> is live and fully backwards compatible, so existing integrations need no changes to integrate the latest version.
