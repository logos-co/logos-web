11:T3829,<p>2025 marked a turning point for Logos as a technical project.&nbsp;</p><p>What had previously existed as a collection of related but independently evolving protocols came together into a single, coherent stack, with a clear identity, shared architecture, and a more deliberate focus on the developer experience.</p><p>Logos underwent a substantive shift towards action, both as a movement and a technology stack, which includes a deeper shift in the way protocols are built, documented, and made available to be used.</p><p>Now, Logos aims to deliver a completely integrated foundational architecture that can support privacy-preserving decentralised applications in real-world conditions.</p><p>As part of the consolidated Logos movement and tech stack, further technical updates on Logos messaging, blockchain, and storage will be published on Logos platforms, including here on the Logos Press Engine.</p><p>For developer-focused highlights on X, please follow&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://x.com/Logos_devs">Logos Tech</a>. For broader updates on the Logos movement as a whole, stay tuned to the main&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://x.com/Logos_network">Logos</a> account. To recap 2025 from the perspective of Logos, the social movement, <a href="/media/article/2025-recap">read this article</a>.</p><h2 id="consolidating-the-logos-stack">Consolidating the Logos stack</h2><figure class="image"><img style="aspect-ratio:2441/1844;" alt="Logos-nov-update-tech-stack.jpg" src="/media-images/Logos_nov_update_tech_stack_645c39bc52-fa7cce9e-750.webp" srcset="/media-images/Logos_nov_update_tech_stack_645c39bc52-fa7cce9e-750.webp 750w, /media-images/Logos_nov_update_tech_stack_645c39bc52-fa7cce9e-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="2441" height="1844" loading="lazy" decoding="async"></figure><p>At the start of 2025, the core technologies that now make up Logos were known as Codex, Nomos, and Waku. Each had its own repositories, documentation, and community touchpoints, and each addressed a different pillar of the decentralised stack.&nbsp;</p><p>By the end of 2025, these components had been .. This consolidation brought clarity to both architecture and purpose.&nbsp;</p><ul><li>Messaging, previously Waku, now forms the private, peer-to-peer communications layer.&nbsp;</li><li>Storage, previously Codex, provides durable, censorship-resistant data availability.&nbsp;</li><li>Blockchain, previously Nomos, serves as the privacy-preserving Layer 1 that anchors execution, settlement, and coordination across the stack.</li></ul><p>For developers, this shift matters because it reframes Logos as a unified ecosystem rather than a set of standalone tools. The stack is private by default and modular by design, with work beginning last year on a plugin-based runtime for decentralised applications to use Logos messaging, storage, and execution modules without centralised dependencies.</p><p>Alongside the technical unification, work began on merging websites, developer documentation, and community spaces. This process is ongoing, but the goal is clear: a predictable and navigable entry point for contributors, with consistent terminology and a shared source of truth.</p><p>We’ll be adding to our&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-docs">documentation</a> over the coming months to make sure that running, building on, and contributing to the Logos technology stack is as easy as possible.</p><p>We remain committed to delivering a private-by-default decentralised stack to defend civil liberties at scale and revitalise civil society, and we welcome builders to join the open-source Logos movement and help create the tools that will deliver a better, more hopeful future for society.</p><h2 id="logos-core-a-modular-runtime-for-developers">Logos Core: A modular runtime for developers</h2><p>Following consolidation, attention turned to the question of how developers actually build on Logos</p><p>The answer taking shape is Logos Core, a modular, plugin-based runtime designed to unify development and deployment across the network.</p><p>Rather than hard coding functionality into a monolithic client, Logos Core allows nodes to dynamically discover and load modules while preserving privacy and minimising metadata leakage.</p><p>Modules will enable developers to easily integrate Logos protocols, such as messaging, storage, and blockchain node deployments. However, Logos Core modules are not limited to the Logos stack; developers can also build their own modules for Logos Core.&nbsp;</p><p>This allows open-source builders to contribute to a crowd-sourced, community-curated library of plugins that make it easier to build decentralised applications.</p><p>This architectural choice is central to the long-term vision of the Logos developer experience. It allows the network to evolve without breaking deployed applications and supports decentralised institutions that can remain resistant to capture over time.&nbsp;</p><p>Whether used by small communities or large operators, the same framework applies, and the same guarantees hold.</p><p>For developers, this means working with a consistent runtime abstraction, with messaging, storage, and blockchain capabilities exposed as composable modules rather than tightly coupled services.</p><h2 id="messaging">Messaging</h2><p>Messaging (previously Waku) is currently the most mature component of the Logos stack, and 2025 saw this set of protocols continuously refined, with several protocols adopted by prominent projects.</p><p>Messaging saw adoption across production and experimental systems, including&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://blog.waku.org/safe-uses-waku-to-power-decentralised-multisig-operations-with-harbour/">integrations with Safe Harbour for decentralised multisig</a> and&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://blog.waku.org/waku-x-taco-p2p-comms-with-decentralised-encryption/">Threshold Access Control (TACo) for decentralised encryption</a>. Logos messaging is also used by the Status app, and this deployment was greatly improved with additional features and made more robust over the course of 2025.</p><p>These integrations demonstrate that while the messaging protocols of the Logos technology stack continue to be built out, they are already capable of supporting scalable, privacy-preserving communications and digital interactions in existing applications with active user bases.</p><p>Throughout the year, the messaging protocols evolved through ongoing research and implementation work. Work on Rate Limiting Nullifiers proceeded apace, with the technology being tightly integrated to secure the network against spam and abuse without relying on accounts or fees.</p><p>Alongside this, early work began on incentive design for light clients, recognising that sustainable, scalable p2p messaging requires mechanisms that align participation with resource usage.</p><p>Parallel to the core messaging work, Logos now also operates a component called AnonComms, which focuses on reducing metadata leakage through mixnets and capability discovery mechanisms.</p><p>Currently, this project’s milestones include building capability discovery over libp2p’s Kademlia DHT, establishing a libp2p-based mixnet with pluggable Sybil and denial-of-service protections, and delivering de-MLS for decentralised group messaging with multiple stewards.</p><p>The&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://roadmap.logos.co/anoncomms/roadmap/">AnonComms roadmap for the year ahead</a> also includes work on a privacy-preserving payment protocol that leverages the Logos blockchain to enable mostly offchain payments to service providers, as well as improvements to Zerokit and the delivery of an RLN prover to support gasless Layer 2 transactions on&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://status.network/">Status Network</a>.</p><h2 id="storage">Storage</h2><p><a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-storage/logos-storage-nim">Storage</a> (previously Codex) revisited its core design in 2025, as it was tightly integrated into the wider technology stack, with its central goal now being to deliver node-side content storage and retrieval functionality.</p><p>Following earlier experimentation, including work with protocols such as BitTorrent, the team stepped back to reassess what a durable, decentralised storage network should look like when aligned with the broader Logos vision.&nbsp;</p><p>The emphasis shifted towards robustness, censorship resistance, and developer usability, rather than maintaining a testnet that no longer reflected the desired architecture.</p><p>As a result, the existing testnet was deliberately paused while the protocol design is being revisited to fit the scope of the protocol within Logos.&nbsp;</p><p>The goal of this change is to realise a more fundamental alignment between storage, messaging, and the blockchain layer, ensuring that developers can rely on a consistent, dependable, censorship-resistant architecture across the stack.</p><h2 id="blockchain">Blockchain</h2><p><a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/logos-blockchain">Logos blockchain</a> (previously Nomos) development in 2025 focused on enabling the foundations required for the upcoming testnet, as well as facilitating the operation of the wider Logos stack and node software.</p><p>Significant progress was made on the protocol’s core milestones last year, providing the team with the foundation to align more with the broader aims of the Logos movement and work on delivering a testnet.</p><p>The base layer of the blockchain protocol provides consensus, data availability, and settlement, and is designed to offload complexity from higher layers wherever possible.&nbsp;</p><p>On top of this sits the&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-blockchain/lssa">Logos State Separation Architecture, or LSSA</a>, which serves as the execution environment for wallets, token operations, and program deployment.</p><p>LSSA introduces a clear separation between public and private states while keeping them interoperable. This enables developers to build applications that span transparent and privacy-preserving contexts without needing to manage cryptography directly. Privacy is enforced by the protocol through zero-knowledge proofs, making it a default property rather than an optional add on.</p><p>A central focus of this work has been decentralised sequencing. Many Layer 2 systems rely on centralised sequencers, which undermines decentralisation and introduces capture risk.&nbsp;</p><p>The blockchain aims to provide decentralised sequencing as a service, allowing sovereign rollups and app chains to avoid running their own consensus while still benefiting from decentralised ordering.</p><p>LSSA will be the first consumer of this model, coordinating block proposals and processing blocks from multiple sequencers according to protocol-defined rules.</p><p>The first public testnet will be rolled out this year. <a target="_blank" rel="noopener noreferrer" href="https://logos.co/node-programme">Sign up now for the node programme</a> and stay tuned to Logos socials and the Logos Press Engine for updates regarding the testnet launch.&nbsp;</p><h2 id="documentation-and-the-developer-experience">Documentation and the developer experience</h2><p>Alongside protocol development, significant effort has gone into improving the developer experience to encourage more open-source contributions and foster a stronger technical community.</p><p>Previously fragmented documentation is being consolidated into&nbsp;<a target="_blank" rel="noopener noreferrer" href="https://github.com/logos-co/logos-docs">a single, coherent structure with consistent naming and navigation</a>.&nbsp;</p><p>Public-facing terminology is being unified under the Logos identity, with Nomos becoming Logos Blockchain, Codex becoming Logos Storage, and Waku becoming Logos Messaging. While legacy names may persist in repositories and specifications for some time, future documentation will use the Logos-first naming scheme.</p><p>The aim is to provide a predictable onboarding path for both operators and developers, where the documentation accurately reflects the current state of the system and can be trusted as a reliable reference.</p><p>In 2026, documentation will be released in phases aligned with project milestones. Operator guides will support those running and maintaining the network, while developer guides will focus on building applications across the messaging, storage, and blockchain layers.</p><h1 id="onward-into-2026">Onward into 2026</h1><figure class="image"><img style="aspect-ratio:1999/1334;" alt="logos-nov-join-movement.jpg" src="/media-images/logos_nov_join_movement_ad2101621d-1c777ab2-750.webp" srcset="/media-images/logos_nov_join_movement_ad2101621d-1c777ab2-750.webp 750w, /media-images/logos_nov_join_movement_ad2101621d-1c777ab2-1400.webp 1400w" sizes="(max-width: 767px) calc(100vw - 32px), 700px" width="1999" height="1334" loading="lazy" decoding="async"></figure><p>2025 was a year of consolidation and intentional action for Logos.
